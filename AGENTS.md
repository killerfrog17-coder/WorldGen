# WorldGen repository instructions

Read `docs/OROGEN_ALIGNMENT.md` (current version-3 scope), `WorldGen_OneShot_Prompt.md`, `docs/FIRST_BUILD_SPEC.md`, `docs/REFERENCE_ANALYSIS.md` and the implementation contracts in `docs/ALGORITHMS.md` before changing generation behavior. `docs/OROGEN_REFERENCE_MAP.md` records independent use of the pinned behavioral reference; never copy GPL reference code without the owner's explicit license decision.

`src/WorldGen.Core` is the sole authoritative generator and targets .NET Standard 2.1. `Serialization` and `Presentation` are shared adapters. CLI, .NET browser worker and Unity runtime call `WorldPipeline`; reapply/cache/edit changes must not create another generation route. Keep geological provenance and the coarse/fine resolution split inspectable. Persistent hydrology is deferred by the owner; do not restore the old lake/river solver.

The determinism contract is seed + complete recipe + algorithm version. Use project-owned named PRNG streams, explicit numerical quantization, ordered graph ties/reductions and stage hashes. Avoid System.Random, engine randomness, GPU decisions, wall time and unordered authoritative iteration. Version output-changing algorithms after the initial release. Golden updates must be intentional and reviewed; never regenerate expectations as part of a passing test run.

Current scope: a fixed 20,000-cell coarse plate/continent base projected onto a detail-dependent 5,000-2,560,000-cell terrain mesh; independent Orogen-aligned terrain/sculpting, two-season climate, and Unity/browser globe/map views. The owner explicitly declined GPL translation on 17 September 2026. Persistent hydrology, Map2 collision contexts, ecological simulation, populations, settlements, civilization/history and local playable terrain are deferred. Preserve `ISeasonalRunoffProvider` only as a future extension boundary.

Build: `powershell -ExecutionPolicy Bypass -File scripts/build.ps1`. This compiles the solution, stages worker assets, and copies shared .NET Standard DLLs into Unity. Test: `dotnet run --project tests/WorldGen.Core.Tests -c Release`. Verify CLI reconstruction: `dotnet run --project src/WorldGen.Cli -c Release -- --preset Preview --verify`.

Browser: `dotnet run --project src/WorldGen.Web -c Release --no-build --urls http://127.0.0.1:5080`; then `npm ci`, `node scripts/browser-check.mjs`, `node scripts/worker-check.mjs`. Restart the server after rebuilding fingerprinted assets. Unity is **6000.6.0f1**, URP **17.6.0**, under `unity/WorldGen.Unity`. Run `scripts/unity-check.ps1` and `scripts/unity-check.ps1 -BuildPlayer -PlayerCheck`. Do not run two editor processes against the same project.

Current recipes use schema 3 / worldgen-3.0.0. Version-1/2 fixtures are historical; current goldens live in `tests/golden/v3`. Detail and Irregularity are generation settings and participate in hashes. `World.CoarseHash` must remain invariant when only those settings change. Earlier first-build instructions are superseded where they conflict with `docs/OROGEN_ALIGNMENT.md`.

Required review: matching all-stage hashes across fresh/reapply/serialized-recipe/cached reconstruction; connected plates/superplates; stable coarse partition but genuinely detail-dependent terrain; full globe/map coverage and crisp cell colors; no generated persistent lakes/rivers; settings parity; cancellation during generation and presentation; bounded Unity uploads; no generator code in JavaScript or Unity. `docs/VALIDATION.md` records available-host evidence and unverified targets. Keep generated caches, binary outputs and screenshots out of source control.
