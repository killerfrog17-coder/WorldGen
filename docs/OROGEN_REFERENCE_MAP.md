# World Orogen reference audit and implementation map

Reference: [planet_heightmap_generation at cc2662b4edd52231c4f65d8765f3ef12cd82d9b7](https://github.com/raguilar011095/planet_heightmap_generation/tree/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7). Source was fetched into a temporary directory outside this repository and inspected before implementation. No Orogen source, assets, parameter tables, or mechanical translations are included here. Its GPL-3.0 license remains relevant to any future proposal to copy code. This implementation is independently written C#.

The executed worker path, rather than the README feature list, is the baseline. It builds a requested sphere, independently constructs a fixed coarse sphere, grows coarse plates and land groups, projects labels, smooths/reconnects them, assigns density, adjusts plate motion, creates super-plates, propagates mantle fields, synthesizes elevation, postprocesses terrain, optionally calculates climate, builds display data, retains regeneration inputs, and reports metrics.

| Executed reference component | Decision | Corresponding C# implementation / reason |
|---|---|---|
| `sphere-mesh.js`: Fibonacci sampling, stereographic Delaunay, closing pole, adjacency, arithmetic dual centers | Deliberately modified concept | `SphericalMesh`: jittered geodesic icosahedral triangulation and spherical barycentric dual. Closed topology, explicit great-circle center distances, dual-edge lengths and spherical cell areas. No projection pole or extra hidden region. |
| `coarse-plates.js`: fixed 20k reference sphere, isolated random stream, noisy nearest-label projection | Preserved concept; deliberately modified resolution policy | `WorldPipeline`, `SphericalMesh`, `Recipe.MacroCellCount`: one canonical mesh per recipe; both hosts render it without resimulating. Resolution is raised to a supported closed mesh with at least 16 cells per microplate on average. No authoritative render-resolution projection. |
| `plates.js`: separated seeds, controlled frontier growth, direction, size governor, compactness, smoothing and reconnection | Deliberately modified concept | `PlateHierarchy.Microplates`: separated seeds and connected weighted graph growth. `Parents`: connected growth over the *microplate* graph, not cells; transported directions, curvature, previous-direction continuity, target area and shared perimeter. Connectivity is constructive rather than repaired by disconnected reseeding. |
| `ocean-land.js`: continent seeds, whole-plate land budgets, continent growth, trapped sea absorption | Deliberately modified concept | `Continents`: connected identity groups and area budgeting with separation/contact tendencies. `Terrain.ProtectInlandSeas`: retains eligible marine remnants. Identity, crust, landmass, ocean connectivity and water-body IDs are distinct. |
| `super-plates.js`: groups neighboring same-type plates, aggregated rotations | Deliberately modified concept | `ParentPlate` aggregates adjacent microplates and target areas. Parent affinity is distinct from active actor identity. Contested interface actors retain independent blended motion. |
| `plate-physics.js`: Euler rotation, drag/size rules, slab pull, ridge push, mantle adjustments | Preserved local motion concept; deferred detailed force heuristics | `Tectonics`: local cross-product rotational motion, normalized parent/fine stress blend and density-aware subduction. Full mantle-force and slab-pull feedback is deferred; no time-integrated geodynamics is claimed. |
| `elevation.js` stage 1: local collision classification and propagated stress | Preserved concept | `Tectonics.Build`: signed normal and tangential motion per shared segment, active versus ghost identity, density-selected subducting side, local stress and physical boundary distance. |
| Stage 2: mountain, coast and tectonic influence fields | Preserved concept; modified distance semantics | `Graph.Distances`: integer-metre Dijkstra with stable ties, retained coast and active-boundary distances. Physical distance is not a shuffled first-visit growth distance. |
| Stage 3: continuous terrain classification / province weights | Preserved concept | `Terrain.Build`: retained normalized fold, craton, basin and plateau weights. These modify the terrain scaffold and remain available after erosion. |
| Stage 4: broad terrain skeleton, asymmetric uplift, basins and ocean floor | Preserved concept; extended collision context | `Terrain`: physical-metre crust, coast, shelf/slope/abyss profiles and weighted semantic kernels. `Tectonics.Context` classifies distance to the main connected ocean; dead ends get stronger/wider uplift, escape faces get fragmented negative relief. |
| Stage 5: oriented phasor ridges | Preserved directional-ridge concept; independently modified synthesis | `Terrain`: boundary-aligned oscillatory parallel ranges, spatial warp, along-strike passes and plateau variation. No constant maximum-elevation wall. Macro resolution limits resolvable ridge spacing. |
| Stage 6: island arcs, volcanic arcs, hotspot trails and LIPs | Preserved concept | `Feature` records drive their own elevation kernels. Arcs offset from subduction, chains trail against local plate motion and decay with age; broader large-igneous swell is separate. |
| Stages 7–10: tectonic-band texture, gated detail, coastal texture and broad land noise | Preserved concept | `Terrain.Noise`: seeded sphere-native trilinear value noise at multiple scales; boundary and province-conditioned relief and coast detail. These are subordinate to the tectonic scaffold. |
| Stage 11: mantle-related dynamic topography | Deferred concept | No mantle field is fabricated. Extension can add a versioned core stage without changing hosts. |
| Stage 12: nonlinear peak compression / height-distribution remapping | Rejected raw-height representation; modified shaping | Heights are directly integer metres. No raw-height to kilometre curve or mismatched import inverse. Features, density and erosion govern the distribution. |
| Stage 13: filling stranded sub-sea continental interiors | Rejected unconditional fill | Enclosed marine blocks are detected and protected before warp/erosion. Final water conditioning never changes authoritative terrain. |
| `terrain-post.js` and worker post stack: warp → pre-erosion snapshot → smoothing/detail → composite erosion → sharpening → creep | Preserved broad ordering; deliberately modified operators | `Terrain` retains tectonic and warped pre-erosion fields; `Erosion` runs five deterministic hydraulic/thermal/glacial passes. Ridge preservation moderates thermal transfer. No hidden always-on creep; all erosional settings zero is a no-op. |
| Internal priority flood used by erosion | Deliberately replaced / extended | `Hydrology` runs **after every elevation mutation**: union-tree depression hierarchy, priority flood, common-level lakes, one stable outlet, preserved terminal basins, watershed IDs, actual contributing area, ordered river reaches. |
| `terrain-config.js`: large tuned constant vocabulary and effective parameter defaults | Preserved explicit configuration philosophy | `Recipe` is the single versioned effective control catalog. Both interfaces reflect its groups/bounds. Constants not exposed are owned by `worldgen-1.0.0`; recipe presets are ordinary values. |
| `terrain-metrics.js`: silhouette, relief, coast, shelf, stress correlation and erosion diagnostics | Preserved inspection philosophy; modified metrics | `World.Metrics`: requested/achieved parent areas, land/crust fractions, landmass counts, preserved actors, active/ghost/context counts, erosion delta, relief, lakes, inland seas, rivers and lower-sea connectivity. Empirical Earth-calibration scoring is deferred. |
| `planet-worker.js`: progress, transferable results, fresh/reapply/edit/cache paths | Preserved worker execution; rejected duplicated orchestration | `WorldPipeline.Generate` is called by `Reapply`, `Reconstruct`, CLI, .NET worker and Unity runtime. No alternate fallback or retained-stage shortcut. Cancellation discards unfinished results. |
| `planet-code.js`: quantized compact recipe codes and legacy format decoding | Deliberately modified concept | `WorldJson`: complete schema-versioned JSON recipes/results, strict setting validation and result integrity verification. Compact share codes and algorithm migrations are deferred. Unknown versions fail explicitly. |
| `planet-mesh.js`: globe/map, overlays, physical conversion and heightmap export | Preserved inspection/export concept; modified hosts | `WorldGen.Presentation.GlobeView`, native WebGL and Unity procedural meshes. 16-bit PGM equirectangular physical heightmap plus CSV and full JSON. Diagnostic layers share one catalog. A separate interactive flat map is deferred. |
| `main.js`: parameter panels, stale state, presets, regeneration and diagnostic switching | Preserved workflow | Blazor `Home` and `WorldGenRuntime`: controls, presets, dirty indicator, progress, cancellation, recipe save/load, result/CSV/heightmap exports, sea-level preview and cell inspection. |
| Worker climate, wind, ocean circulation, precipitation, temperature, Köppen stages | Deferred concept | `ISeasonalRunoffProvider` is the extension boundary. No seasonal discharge, climate or ecology is synthesized. |

Additional changes required by this project have no direct Orogen equivalent: contested microplate eligibility and quota warnings; full microplate provenance and weighted adjacency; inactive ghost-seam history; explicitly named foreland basins; protected inland-sea origin; persistent depression and river records; canonical cross-runtime hashes.

The reference worker retains plate labels, vectors/densities, pre-post terrain, stress, coarse inputs and several damping fields. Its fresh/reapply/edit paths differ in supplied inputs (documented in `REFERENCE_ANALYSIS.md`). Here cache reconstruction intentionally pays for a complete replay. There is exactly one dependency order to inspect.

This is a macro terrain synthesizer with geological heuristics, not a geological-history integrator or a replacement for scientific geodynamic/erosion software. See `ALGORITHMS.md` for implemented numerical contracts and limitations.
